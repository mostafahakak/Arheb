Authentication Public

Live app login (Twilio OTP)

POST /api/auth/register and POST /api/auth/verify-otp use Twilio Verify on the server (same URLs as the production app). No Firebase SMS on these endpoints anymore.

  • Required on Render: TWILIO_ACCOUNT_SID (AC…), TWILIO_AUTH_TOKEN, TWILIO_VERIFY_SERVICE_SID (VA… from Twilio Console → Verify → Services).
  • Not the same as Messaging Service: MG… is TWILIO_MESSAGING_SERVICE_SID (optional template WhatsApp fallback only).
  • SMS OTP (like old Firebase): TWILIO_REGISTER_OTP_CHANNEL=sms on the server.

After Request OTP, sessionInfo is filled automatically. If it starts with VE…, Twilio Verify sent the code (SMS or WhatsApp per server config).

POST /api/auth/verify-otp — returns token (Bearer JWT). firebaseToken may be null with Twilio.

POST /api/auth/firebase/register + /api/auth/firebase/verify-otp — requires FIREBASE_API_KEY on server and reCAPTCHA below.

WhatsApp OTP Public

Backend configuration (one active path)

Set the API base URL in the header. This page calls the same production endpoints as your apps.

  • Live app (same as Authentication tab): POST /api/auth/register + /api/auth/verify-otp — Twilio Verify; set TWILIO_VERIFY_SERVICE_SID (VA…, not MG…).
  • Twilio Verify (WhatsApp): TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_VERIFY_SERVICE_SID (must start with VA from Verify → Services — not AC, not MG). Enable WhatsApp on the service if using WhatsApp.
  • Twilio Verify (SMS, no WhatsApp): same three vars + TWILIO_REGISTER_OTP_CHANNEL=sms (or TWILIO_VERIFY_CHANNEL=sms) on the server.
  • Twilio Messaging Service (MG…): optional TWILIO_MESSAGING_SERVICE_SID — only for Content-template WhatsApp fallback, not for Verify OTP.
  • Twilio Messaging (template): above + TWILIO_WHATSAPP_FROM, TWILIO_WHATSAPP_OTP_CONTENT_SID.
  • Meta Cloud API: WHATSAPP_ACCESS_TOKEN, WHATSAPP_PHONE_NUMBER_ID, template env vars.

After Send code, verificationId is filled automatically. If it starts with VE…, you are on Twilio Verify; use the code from the WhatsApp message (length may vary). Otherwise it is a UUID and the code is typically 6 digits.

Customer flow uses verificationId + OTP like the app. Driver flow only works for mobiles already registered as drivers.

POST /api/auth/whatsapp/send-code

Customer — Verify code

POST /api/auth/whatsapp/verify-code

POST /api/driver/whatsapp/send-otp
